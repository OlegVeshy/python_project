# 📅 CalendarBot

Телеграм-бот для управления календарём с естественным языковым вводом. Пересылаешь боту любое сообщение о предстоящем событии — он сам разбирает его через LLM, создаёт событие, находит оптимальное время и синхронизирует с Google Calendar.

## Идея проекта

Обычные календари требуют ручного ввода: выбрать дату, время, название. Этот бот работает иначе — ты просто пишешь или пересылаешь сообщение в свободной форме.
Бот разбирает текст через LLM, извлекает структурированное событие и добавляет его в календарь. Умеет находить свободные слоты с учётом уже занятого времени, обрабатывать повторяющиеся события, синхронизироваться с Google Calendar и уведомлять о предстоящих событиях.

## Библиотеки

- aiogram — API для телеграм бота
- anthropic / openai — LLM для парсинга событий
- SQLite через aiosqlite (возможно Pandas, но менее вероятно) — хранение событий
- google-api-python-client — Google Calendar API
- python-dateutil — работа с повторяющимися событиями (rrule) и парсинг относительных дат
- APScheduler — планирование уведомлений
- Dataclass — хранение событий
- (возможно) pydantic — проверка корректности данных, полученных от LLM

#### Нетривиальная библиотека

В качестве такой библиотеки скорее всего будет выбрана `python-dateutil`, так как она простая и одновременно полезная для проекта. С помощью ее функционала возможно:

1. Разрешение относительных дат (`"следующий вторник"`, `"через две недели"`) в конкретные `datetime` объекты.
2. (Возможно) Реализация повторяющихся событий через `rrule` — «каждый понедельник», «первая среда месяца». Правило хранится как объект и разворачивается в конкретные даты только при необходимости.

## Вероятные фичи к первой итерации

### 1. Парсинг событий из произвольного текста

Пользователь пересылает или пишет боту сообщение на естественном языке. Бот отправляет текст в LLM с заготовленным промптом, получает структурированный JSON с полями события (название, дата начала/конца, статус уверенности). Если уверенность низкая — переспрашивает уточняющий вопрос. Событие сохраняется в локальную БД.

### 2. Алгоритм поиска свободного слота

Пользователь запрашивает: «найди мне окно на час в среду». Алгоритм:
- собирает все занятые интервалы за день
- сливает пересекающиеся
- находит свободные окна подходящей длины в рамках рабочих часов
- ранжирует их по score: буфер до/после соседних событий, время суток, предпочтения пользователя

### 3. Отдельный хендлинг повторяющихся событий (возможно дедлайнов тоже)

При парсинге отдельно распознавать повторяющиеся события. Правило сохраняется как `rrule`-объект. При отображении расписания и поиске слотов правило разворачивается только в нужном временном диапазоне — без хранения тысяч отдельных записей.

## Вероятные фичи к второй итерации

### 1. Двусторонняя синхронизация с Google Calendar

Push и pull в гугл календарь с разрешением конфликтов: если одно событие изменено и в боте и в Google — применяется настраиваемая стратегия разрешения

### 2. Планировщик уведомлений

Хранение приоритетной очереди предстоящих уведомлений. При изменении или удалении события — уже запланированный `asyncio.Task` отменяется и пересчитывается. Поддерживает несколько напоминаний на одно событие и настраиваемые правила (рабочие vs личные события).
